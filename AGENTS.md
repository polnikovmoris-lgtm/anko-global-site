# ANKO Global — правила работы Codex

## Назначение проекта

Это исходный репозиторий сайта `ankoglobal.by`. Публикуемая версия находится
только в `site/`. Остальные каталоги предназначены для разработки, проверок и
документации.

## Язык и взаимодействие

- Общаться с владельцем проекта на русском языке, простыми словами.
- Перед существенным изменением кратко объяснять ожидаемый результат.
- Не публиковать изменения на действующий сайт и не менять DNS, хостинг,
  почтовую доставку или внешние сервисы без отдельного явного подтверждения.
- До подтверждения владельца результат показывать в предпросмотре или
  отдельной ветке.

## Структура

- `site/` — единственное содержимое, которое можно размещать в web-root
  (`public_html`/`www`).
- `source/` — редактируемые исходные CSS и JavaScript, если соответствующий
  файл там существует.
- `tools/` — скрипты сборки и проверок.
- `audit/` — результаты прежних и текущих проверок.
- `docs/` — документация, отчёты и журнал изменений.
- `hosting/` — отдельные настройки старых доменов; не смешивать с `site/`.

## Безопасность и сохранность

- Никогда не записывать пароли, токены, OAuth-данные и содержимое `.env` в Git.
- Не менять адрес получателя заявок, юридические реквизиты, телефоны, домены,
  аналитику или правила AI-краулеров без явного указания владельца.
- Не публиковать выдуманные цены, характеристики, сертификаты, наличие,
  партнёрство или происхождение товара.
- Перед заменой изображения товара сверять модель, производителя и назначение.
- Не удалять материалы и страницы только потому, что они кажутся устаревшими:
  сначала проверить ссылки, Sitemap, поиск и редиректы.
- Сохранять обратную совместимость URL; при переименовании создавать корректный
  постоянный редирект и исключать старый URL из Sitemap.

## Порядок изменения

1. Прочитать релевантную документацию и определить затрагиваемые страницы.
2. Проверить чистоту рабочей ветки и не затрагивать посторонние изменения.
3. Внести минимальное связное изменение.
4. При изменении `source/css/style.css`, `source/js/main.js` или
   `source/js/search.js` синхронизировать соответствующий файл в `site/`.
5. Обновить поисковый индекс, Sitemap, structured data и cache-busting версию,
   если изменение влияет на каталог, URL, метаданные, CSS или JavaScript.
6. Запустить `make check`.
7. Для интерфейсных изменений проверить минимум ширины 320, 375, 390, 768,
   1024, 1440 и 1920 px, клавиатурное управление и отсутствие горизонтального
   переполнения.
8. Кратко записать пользовательски значимое изменение в `docs/CHANGELOG.md`.

## Обязательные проверки

- `make check` — основной локальный контроль.
- PHP lint всех файлов обязателен, когда PHP доступен.
- Для изменения интерфейса одной статической проверки недостаточно:
  требуется браузерная проверка затронутых страниц на desktop и mobile.
- Для форм дополнительно проверить CSRF, согласие, ограничения размера и
  частоты запросов, безопасные ошибки и реальную доставку на staging/HTTPS.
- После публикации проверить HTTPS, редиректы, CSP/HSTS, кеширование, Sitemap,
  robots.txt, форму, Lighthouse и Core Web Vitals.

## Git-процесс

- Не работать напрямую в `main` для обычных изменений.
- Использовать ветку `agent/<краткое-название>`.
- Делать один понятный набор изменений на коммит.
- Перед слиянием показывать владельцу результат и список проверок.
- Слияние и публикация на хостинг — разные действия. Слияние в GitHub не
  означает разрешение обновить действующий сайт.
